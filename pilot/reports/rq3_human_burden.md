# 追加分析: 「コメントはAI、最終承認は人間」構造での人間の負担

実行スクリプト: `scripts/pilot/rq3_human_burden.py`
実施日: 2026-09-16
きっかけ: `Collaborator or Assistant?`(arXiv:2605.08017)との緊張関係の議論で、ユーザーから「コメントはAIで最終承諾は人間のイメージ。だから人間の負担が増えてそう」という仮説が出た。

## 指標

- **`n_ai_reviews_before_approval`**: PRで人間の最初のAPPROVEDより前に付いていたagentレビュー数(＝人間が承認前に読まされたAIコメントの量)
- **`human_approval_lag_days`**: PR作成から人間の最初のAPPROVEDまでの日数

これらをそのモジュールの生成関与度`A_prime`(trailer込み)に回帰する。39リポジトリ、人間がAPPROVEDを出したPR 140,250件。

## 基本統計

| 指標 | 値 |
|---|---|
| 承認前のAIレビュー数(全体平均) | 0.336件 |
| 承認前に1件以上AIレビューがあったPRの割合 | 18.9% |
| 承認までの日数(平均) | 4.53日 |
| 承認までの日数(中央値) | 0.29日(≈7時間) |

## ★結果: 両方とも強く有意

```
log(1+承認前AIレビュー数) ~ A_prime + log(PR数) + module_FE + time_FE
承認までの日数            ~ A_prime + log(PR数) + module_FE + time_FE
```

| 従属変数 | A_primeの係数 | p値(moduleクラスタ) | p値(repoクラスタ, n=39) |
|---|---|---|---|
| **承認前AIレビュー数(log)** | **+0.179** | <0.0001 | **0.0071** |
| **承認までの日数** | **+3.52** | 1.0e-08 | **0.0003** |

**両方ともmodule・repoクラスタどちらでも強く有意。** AI関与度が高いモジュールほど:
1. 人間が承認する前に読む・判断材料にするAIレビューの数が多い
2. 人間の最終承認までにかかる時間が長い(約3.5日/A_prime 1単位あたり、実質的な遅延)

## 解釈

**ユーザーの仮説を支持する頑健な結果。** 「評価工程の人間比率が下がっている」(H1b、これまでの主解析)ことと、「残っている人間の評価業務(最終承認)はむしろ負担が増えている」ことが、同時に起きている可能性が高い。

これは`Collaborator or Assistant?`論文(マージ承認はほぼ人間に残る)との緊張関係を解消する、まさに求めていた整理を与える:
- **AIは評価工程のボリューム(コメント数・レビュー提出件数)を代替している → H1bで検出した「人間比率の低下」**
- **しかし最終承認という質的判断は依然として人間が担う → Collaborator or Assistant?論文の発見と整合**
- **その結果、人間の最終承認者は「AIが大量に出したコメントを読み込んだ上で判断する」という、質的に重い仕事を負っている → 承認までの時間が延びている**

つまり両論文は矛盾しておらず、**「評価工程が『AIによる大量の一次スクリーニング』と『人間による重い最終判断』に分業化している」**という統合的な描像が描ける。これは本研究の主張をむしろ強化する発見。

## ★頑健性チェック: PR規模(変更行数・ファイル数)を統制しても結果は変わらない

「AI関与度が高いモジュールは複雑な変更が多く、それ自体がAIレビュー数・承認時間を押し上げているだけではないか」という交絡懸念を検証するため、`log(1+PR変更行数)`・`log(1+PR変更ファイル数)`を統制変数に追加して再実行した。

```
log(1+承認前AIレビュー数) ~ A_prime + log(PR数) + log(PR変更行数) + log(PR変更ファイル数) + module_FE + time_FE
承認までの日数            ~ A_prime + log(PR数) + log(PR変更行数) + log(PR変更ファイル数) + module_FE + time_FE
```

| 従属変数 | | A_primeの係数 | p値(module) | p値(repo, n=39) |
|---|---|---|---|---|
| 承認前AIレビュー数(log) | 統制前 | +0.179 | <0.0001 | 0.0071 |
| 承認前AIレビュー数(log) | **統制後** | **+0.166** | <0.0001 | **0.0090** |
| 承認までの日数 | 統制前 | +3.52 | 1.0e-08 | 0.0003 |
| 承認までの日数 | **統制後** | **+2.84** | 2.2e-06 | **9.1e-05** |

**係数はわずかに減少したが、有意性はむしろ強まった(承認日数モデルのp値は0.0003→0.00009)。** PR変更行数自体は両モデルで有意に正(大きいPRほど時間がかかるのは当然)だが、それを統制してもA_primeの独立した効果は消えない。**「AI関与度が高いモジュールでは複雑なPRが多いから」という交絡だけでは説明できず、承認前のAIレビュー数・承認までの時間の増加は、PR複雑度とは別にAI関与度そのものと結びついている。**

## 限界・持ち越した論点

- [ ] `n_ai_reviews_before_approval`は「AIレビューの量」であって「質(指摘の妥当性・読む負担の大きさ)」は見ていない
- [ ] PR複雑度以外の交絡(モジュールの重要度・変更の種類等)は未検証
