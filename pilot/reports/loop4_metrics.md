# Loop 4 — 指標の算出

対象: `home-assistant/core`、`grafana/grafana`
実行スクリプト: `scripts/pilot/loop4_metrics.py`
実施日: 2026-09-12

## やったこと

module×month のパネルを作り、H_I, H_G, H_E, A を計算した。legacy_bot は主解析から除外(研究設計書§3.1)。
Loop1の発見(actor loginだけではagent関与を大きく過小評価する)を受け、**commit trailerでのagent検出を反映した H_G_prime / A_prime も併せて計算**した(感度分析)。

```
H_G(m,t)       = human作成PR数 / 全PR数                          (agent = PR作成者accountのみで判定)
H_G_prime(m,t) = (human作成 かつ trailerにagent識別子なし)PR数 / 全PR数   (agent = accountまたはtrailerで判定)
A       = 1 - H_G
A_prime = 1 - H_G_prime
```

## 結果

| 指標 | home-assistant/core | grafana/grafana |
|---|---|---|
| モジュール数(イベントあり) | 1909 | 704 |
| 月数 | 42 | 40 |
| パネル行数 | 8708 | 3496 |
| 有効セル割合 H_I(分母≥3) | 1.6% | 3.1% |
| 有効セル割合 H_G | 20.5% | 33.4% |
| 有効セル割合 H_E | 62.3% | 53.5% |
| **A 平均(login のみ)** | **0.0010** | **0.0062** |
| **A_prime 平均(trailer込み)** | **0.153** | **0.108** |
| A_prime 標準偏差 | 0.319 | 0.263 |

## ★重要な発見

**AはA_primeの1/100程度しかない。** actor login だけでagent関与を測ると、両リポジトリともAIエージェントの生成関与度はほぼゼロに見えるが、commit trailer を反映すると10〜15%に跳ね上がる。これはLoop1で発見した「AIエージェントは人間のアカウントの下で使われることが大半」という実態と整合する。

**この差は Loop5(★最重要ゲート)の結論を左右する。** 詳細は `loop5_variance.md`。

## ゲート判定(案。判定は人間が行う)

| 指標 | 基準 | 結果 | 判定 |
|---|---|---|---|
| 有効セル(分母≥3)の割合 | ≥50% | H_E は満たす(53.5-62.3%)。H_G(20.5-33.4%)・H_I(1.6-3.1%)は満たさない | **モジュール粒度が細かすぎる可能性。CODEOWNERSの粗い階層でまとめるか、H_I工程自体をLoop3の判断と合わせて縮小するか検討** |
| パネル行数 | モジュール数×月数に対して十分か | 8708/1909÷42=約11%、3496/704÷40=約12%(欠測が多い) | モジュール数が多すぎて疎になっている |

## 持ち越した論点

- [ ] **A の定義をlogin単位・trailer込みのどちらで確定するか(Loop1の論点と共通)**。事前登録では一方に決める必要がある
- [ ] モジュール数が1000+と非常に多く、有効セルが薄い。CODEOWNERSの粗い階層(親ディレクトリ単位)への統合を検討するか
